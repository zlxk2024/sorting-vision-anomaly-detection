# AI错分视觉模型验证需求与执行方案

## 1. 项目目标

基于手机固定机位采集的视频，先做一版离线 PoC 验证，判断“视觉检测 + 目标跟踪 + ROI区域判断 + 异常规则”是否能够识别分拣过程中的典型错分异常。

本阶段不要求直接上线实时告警，目标是验证技术路线、标注规范、数据质量和三类核心异常的可识别性。

## 2. 当前输入数据

- 示例视频：`/Users/lixing.guo/Desktop/异常检测视频/快递分类视频.mp4`
- 视频参数：约 39.47 秒，720×1280，约 30fps，手机竖屏拍摄
- 当前判断：可以作为需求示例和补充样本，但不建议作为唯一训练集

手机视频适合用于：

- 定义异常类型
- 验证检测、跟踪、ROI判断逻辑
- 快速制作小样本数据集
- 形成后续工业相机采集规范

后续正式上线前，应补充最终安装相机视角的视频数据。

## 3. 第一版重点异常类型

本阶段只验证三个最明显、最有业务价值的异常类型。

| 编号 | 异常类型 | 标签名 | 判断含义 |
|---|---|---|---|
| 1 | 抽屉开门，不掉件 | `open_no_drop` | 抽屉/闸门打开后，包裹未在规定时间内离开小车或进入落格区域 |
| 2 | A格开门，件掉到B闸口 | `wrong_chute` | 开门格口是 A，但包裹轨迹最终进入 B 格口区域 |
| 3 | 一个小车装2个及以上包裹 | `multi_parcel_on_cart` | 同一小车/抽屉承载区域内同时存在 2 个及以上包裹 |

## 4. 技术路线建议

建议采用组合式方案，不建议直接训练一个“正常/错分”分类模型。

```text
手机视频输入
  ↓
YOLO 检测包裹
  ↓
ByteTrack / BoT-SORT 目标跟踪
  ↓
手动画格口、小车、落点 ROI
  ↓
轨迹进入区域判断
  ↓
规则判断三类异常
  ↓
输出事件结果与可视化视频
```

### 4.1 YOLO 的角色

YOLO 作为“眼睛”，主要负责检测包裹位置。

第一版最小模型类别：

- `parcel`：包裹

如数据质量允许，可扩展：

- `cart`：小车/抽屉承载区
- `gate_open`：开门状态
- `gate_closed`：关门状态

但建议第一版先保持简单：只训练或检测 `parcel`，格口和小车区域优先用人工 ROI 配置。

### 4.2 是否必须训练模型

可以先用现有 YOLO 预训练模型做流程验证，但不建议直接作为最终识别模型。

不训练模型可验证：

- 纸箱是否能被检测
- 包裹轨迹能否被跟踪
- ROI 判断逻辑能否跑通
- 三类异常规则能否输出事件

但通用模型可能会漏检：

- 黑色快递袋
- 软包
- 反光袋
- 扁平件
- 运动模糊包裹

因此建议执行顺序：

1. 先用现有 YOLO 跑示例视频，做无训练 baseline。
2. 如果包裹漏检明显，标注少量关键帧微调 `parcel` 检测模型。
3. 用微调模型重新跑视频，对比检测稳定性和异常识别效果。

## 5. 数据采集要求

### 5.1 手机拍摄要求

现场同事需要做：

- 手机固定，不要手持晃动
- 一个机位覆盖 3-4 个格口
- 角度尽量接近未来工业相机视角
- 包裹、小车、抽屉开门、落格区域都要在画面内
- 保留原始视频，不要用微信压缩文件
- 每段视频建议 1-3 分钟
- 同时采集正常样本和异常样本

### 5.2 文件命名建议

```text
日期_产线_机位_主要场景_序号.mp4
```

示例：

```text
20260724_line1_phone_pos1_normal_001.mp4
20260724_line1_phone_pos1_open_no_drop_001.mp4
20260724_line1_phone_pos1_wrong_chute_001.mp4
20260724_line1_phone_pos1_multi_parcel_001.mp4
```

### 5.3 现场事件记录表

现场同事需要同步记录异常事件，避免算法工程师在长视频里人工寻找异常。

| 文件名 | 时间点 | 异常类型 | 开门格口 | 实际落格 | 备注 |
|---|---|---|---|---|---|
| 001.mp4 | 00:21 | 开门不掉件 | 3号 | 无 | 清晰 |
| 002.mp4 | 00:18 | A开门掉B | 1号 | 2号 | 有遮挡 |
| 003.mp4 | 00:12 | 一车多件 | 4号小车 | - | 两个包裹 |

如现场方便，录制时可口头报点：

```text
第3格，开门不掉件
第1格开门，掉到第2格
这辆小车两个件
```

视频有声音时，后期可快速定位异常。

## 6. 样本量建议

以“事件数”为核心，不以“视频条数”为核心。

### 6.1 最低 PoC 样本量

| 类型 | 最低数量 |
|---|---:|
| 正常落格 | 200-300 个事件 |
| 抽屉开门不掉件 | 30-50 个事件 |
| A格开门掉B格 | 30-50 个事件 |
| 一车多件 | 30-50 个事件 |
| 总事件数 | 300-450 个左右 |

### 6.2 更稳妥样本量

| 类型 | 建议数量 |
|---|---:|
| 正常落格 | 500+ 个事件 |
| 抽屉开门不掉件 | 100+ 个事件 |
| A格开门掉B格 | 100+ 个事件 |
| 一车多件 | 100+ 个事件 |
| 总事件数 | 800+ 个事件 |

建议第一轮采集 30-60 分钟手机固定机位有效视频。

## 7. 标注建议

### 7.1 标注分工

现场同事：

- 固定拍摄视频
- 记录异常时间点
- 初步归类异常类型
- 保留原始视频

算法工程师：

- 制定标签体系
- 切分事件片段
- 抽关键帧
- 标注包裹框、ROI 和事件标签
- 训练/验证模型
- 输出异常识别结果

### 7.2 图像标注内容

第一版建议标注：

- `parcel`：包裹框

可选标注：

- `cart`：小车/抽屉承载区
- `gate_open`：闸门打开
- `gate_closed`：闸门关闭

### 7.3 ROI 区域配置

格口位置固定，建议先人工配置 ROI，而不是训练模型识别格口。

需要配置：

- `chute_A_roi`
- `chute_B_roi`
- `chute_C_roi`
- `chute_D_roi`
- `cart_lane_roi`
- 可选：`drop_zone_roi`

ROI 可以用多边形表示。

### 7.4 事件级标注字段

| 字段 | 示例 |
|---|---|
| `video_id` | `line1_phone_001.mp4` |
| `event_id` | `E0001` |
| `cart_id` | `cart_03` |
| `open_chute` | `A` |
| `target_chute` | `A` |
| `actual_chute` | `B` / `none` |
| `gate_open_time` | `00:20.35` |
| `drop_time` | `00:21.10` / `none` |
| `parcel_count_on_cart` | `1` / `2` / `3` |
| `label` | `open_no_drop` / `wrong_chute` / `multi_parcel_on_cart` |
| `confidence_note` | `清晰` / `遮挡` / `模糊` |

## 8. 异常规则定义

### 8.1 开门不掉件

规则：

```text
检测到指定抽屉/格口开门后，
若 T 秒内包裹没有离开小车区域，
且没有进入任何格口 ROI，
则判定 open_no_drop。
```

建议初始阈值：

- `T = 0.8 - 1.5 秒`
- 需要根据视频帧率和现场速度调参

### 8.2 A格开门，掉到B闸口

规则：

```text
已知开门格口为 A，
跟踪对应包裹轨迹，
如果包裹中心点最终进入 B 格口 ROI，
且 B != A，
则判定 wrong_chute。
```

需要输入：

- 开门格口
- 包裹轨迹
- 各格口 ROI

### 8.3 一车多件

规则：

```text
在同一个小车/抽屉承载区域内，
同时检测到 parcel_count >= 2，
并持续超过 N 帧，
则判定 multi_parcel_on_cart。
```

建议初始阈值：

- `N = 5 - 10 帧`
- 避免瞬时误检导致误报

## 9. 算力与工具建议

### 9.1 训练算力

如果微调 YOLO 检测模型，PoC 阶段一张普通 NVIDIA 显卡即可。

| 配置 | 适用情况 |
|---|---|
| RTX 3060 / 4060，8GB 显存 | 最小验证，可训练 YOLO 小模型 |
| RTX 4070 / 4080，12-16GB 显存 | 比较舒服，训练和调参更快 |
| RTX 4090 / A5000 / L40S | 云端训练，多轮实验更合适 |

若标注 1000-3000 张关键帧：

- RTX 3060：几十分钟到 2 小时
- RTX 4070/4080：十几分钟到 1 小时
- RTX 4090：通常十几到几十分钟

### 9.2 软件工具

建议：

- YOLOv8 / YOLO11：目标检测
- ByteTrack / BoT-SORT：目标跟踪
- OpenCV：视频读取、ROI 判断、可视化
- CVAT / Label Studio / Roboflow：数据标注
- Python：规则验证脚本

## 11. 建议执行步骤

1. 确认手机视频采集规范。
2. 采集 30-60 分钟固定机位视频。
3. 现场同事填写事件记录表。
4. 算法工程师抽取关键帧。
5. 标注 `parcel`，配置格口和小车 ROI。
6. 用现有 YOLO 模型跑 baseline。
7. 加入 ByteTrack / BoT-SORT 跟踪。
8. 编写三类异常规则。
9. 输出可视化视频和事件结果表。
10. 评估现有模型是否足够。
11. 如漏检明显，标注 1000-3000 张关键帧微调 `parcel` 检测模型。
12. 对比微调前后效果。
13. 形成 PoC 结论和下一阶段工业相机采集建议。

## 12. 当前结论

本项目第一版建议采用：

```text
YOLO 检测包裹 + 跟踪算法 + 手工 ROI + 规则判断
```

不建议第一版直接训练“错分分类模型”。

不训练模型可以做流程验证，但稳定识别黑袋、软包、运动模糊包裹时，大概率需要微调一个自己的 `parcel` 检测模型。

手机视频适合启动 PoC，但正式上线前应补充工业相机视角数据。
