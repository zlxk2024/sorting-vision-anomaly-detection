# 无 PLC 条件下 AI 错分视觉检测优化方案

## 1. 结论

当前没有 PLC/WCS 开门信号，也可以做，但算法不能再依赖“设备告诉我哪个门开了”。需要改成纯视觉判断：

```text
视频识别门/抽屉状态
        +
视频识别包裹位置
        +
连续帧计时状态机
        ↓
判断开门未落、滑歪、两件同框、掉错格口
```

核心优化方向：

- 不让多模态大模型直接自由判断异常；
- 用视觉模型识别包裹、抽屉/格口开合、滑道区域；
- 用状态机判断动作是否超时；
- M3 只作为前期预标注助手，帮人工找候选片段。

## 2. 为什么没有 PLC 也能做

PLC 的作用主要是告诉系统：

- 哪个格口/抽屉打开；
- 什么时候打开；
- 理论目标格口是哪个；
- 当前小车/包裹对应哪个格口。

没有 PLC 时，这些信息要从画面里推断：

| PLC 可提供的信息 | 无 PLC 替代方式 |
|---|---|
| 开门时间 T0 | 视觉识别抽屉/格口从关闭变为打开 |
| 开门位置 | 视觉检测哪个抽屉/格口发生开合 |
| 包裹是否释放 | 视觉跟踪包裹是否离开小车/释放区 |
| 是否落入正确袋口 | 视觉跟踪包裹轨迹和最终落点 |

因此无 PLC 方案可行，但比有 PLC 更依赖摄像头角度、帧率、标注质量和规则设计。

## 3. 开门未落的纯视觉判断逻辑

开门未落不是单帧判断，而是连续时间判断。

### 3.1 需要识别的对象

至少需要识别三类视觉对象：

- `parcel`：包裹，包括纸箱、黑袋、白色软包、小件；
- `drawer/gate`：抽屉、闸门、翻板、格口开合机构；
- `chute_zone`：滑道、格口入口、袋口区域。

### 3.2 状态机

```text
状态1：等待包裹进入释放区
        ↓
状态2：检测到门/抽屉打开
        ↓
状态3：开始计时
        ↓
状态4：判断包裹是否进入滑道
        ↓
正常：包裹在阈值内离开释放区
异常：超过阈值仍停留在释放区
```

### 3.3 推荐阈值

前期可以先用经验阈值，后续用现场正常样本统计修正。

| 判断项 | 初始建议 |
|---|---:|
| 抽帧/算法处理频率 | 10-30 fps |
| 疑似开门未落阈值 | 0.5 秒 |
| 确认开门未落阈值 | 0.8-1.0 秒 |
| 连续帧最低数量 | 5-10 帧 |

示例：

```text
18.0s：门打开，包裹在释放区
18.2s：包裹仍在释放区
18.4s：包裹仍在释放区
18.6s：包裹仍在释放区
18.8s：包裹仍在释放区

连续 0.8 秒未进入滑道，可判疑似/确认开门未落。
```

### 3.4 伪代码

```python
if gate_state changed from closed to open:
    gate_open_time = current_time
    state = "gate_open"

if state == "gate_open":
    if parcel_in_release_zone:
        stay_time = current_time - gate_open_time
    else:
        state = "released"

    if stay_time >= confirm_threshold:
        alarm("open_no_drop")
```

如果门状态识别不稳定，可以不用“门打开”作为唯一触发条件，而采用双触发：

```text
触发条件 A：视觉检测门打开
触发条件 B：包裹进入释放区并停留不动

A 或 B 满足后开始观察；
A + B 同时满足时提高置信度。
```

## 4. 21 秒场景应该怎么优化

21 秒这个场景，M3 已经能识别“两件同框”，但没有稳定判断开门未落。

原因是 M3 没有真正做时间状态机。它看到包裹在小车上移动，会倾向判断“正常移动”。

优化方式：

### 4.1 分两步判断

第一步：数包裹。

```text
21.0s：两个包裹同框
21.2s：两个包裹同框
```

先标记：

```json
{
  "two_parcels_visible": true
}
```

第二步：判断释放失败。

```text
如果其中一个包裹位于释放区/开口区域；
并且连续多帧没有进入滑道；
则判 open_no_drop。
```

### 4.2 标签拆分

建议不要把 21 秒直接只标成一个标签。可以拆成两个可组合标签：

```text
two_parcels_visible
open_no_drop
```

如果后续能确认两个包裹在同一个小车，再额外标：

```text
multi_parcel_on_same_cart
```

这样标注数据更干净，模型也更容易学。

## 5. 滑歪/偏离路线的无 PLC 判断逻辑

滑歪不能只看上半部分，要看完整轨迹：

```text
释放区 → 滑道 → 袋口
```

推荐把画面划成三个 ROI：

| ROI | 用途 |
|---|---|
| 释放区 ROI | 看包裹是否从抽屉/小车出来 |
| 滑道 ROI | 看包裹是否居中下滑、是否贴边 |
| 袋口 ROI | 看最终落点是否正确 |

滑歪判断：

```text
包裹进入滑道
        ↓
跟踪包裹中心点轨迹
        ↓
判断是否偏离本格口中心线
        ↓
如果偏移超过阈值或跨越边界，标 slide_abnormal
```

初始规则：

- 包裹中心点距离本滑道中心线超过滑道宽度的 35%-40%，判疑似滑歪；
- 连续 3-5 帧贴边，判滑歪；
- 从相邻格口边界出画，判滑歪/疑似错格；
- 最终进入相邻袋口，判 wrong_chute。

## 6. 多模态大模型 M3 的最佳使用方式

没有 PLC 时，M3 仍然有价值，但不要让它做最终裁判。

推荐定位：

```text
M3 = 预筛选/预标注助手
视觉模型 + 状态机 = 正式算法雏形
人工 = 最终确认训练数据
```

M3 适合做：

- 从长视频里找候选异常时间段；
- 对候选标签做 yes/no/uncertain 核验；
- 生成标注说明；
- 辅助抽帧；
- 帮人工减少看视频时间。

M3 不适合单独做：

- 实时报警；
- 最终训练标签；
- 复杂开门状态判断；
- 高可靠格口归属判断。

## 7. 无 PLC 版本推荐实施流程

### 阶段一：视频预标注

```text
手机/工业相机视频
        ↓
按 0.2s 或 0.5s 抽帧
        ↓
M3 找候选异常片段
        ↓
人工确认
        ↓
形成事件级标签
```

事件级标签示例：

```json
{
  "video": "快递分类视频.mp4",
  "start_time": "17.8s",
  "end_time": "18.8s",
  "labels": ["open_no_drop", "white_parcel"],
  "human_verified": true
}
```

### 阶段二：目标检测标注

对确认后的候选片段抽帧，标注：

- 包裹框；
- 抽屉/格口框；
- 滑道区域；
- 袋口区域；
- 开/关状态。

### 阶段三：训练视觉模型

训练至少两个模型/模块：

1. 包裹检测模型：识别纸箱、黑袋、白袋、小件；
2. 机构状态模型：识别抽屉/格口开合状态。

### 阶段四：上线状态机

实时流程：

```text
相机视频流
        ↓
包裹检测
        ↓
门/抽屉状态检测
        ↓
包裹轨迹跟踪
        ↓
时间阈值判断
        ↓
报警灯/音响/后台记录
```

## 8. 对摄像头的建议

无 PLC 情况下，摄像头更重要。

建议：

- 至少 1080p；
- 推荐 60 fps；
- 快门速度要高，避免包裹运动模糊；
- 固定安装，不能手持抖动；
- 角度要同时看到：抽屉/格口、滑道、袋口；
- 光照稳定，避免强反光；
- 一个相机尽量不要覆盖过多格口，避免包裹太小。

## 9. 当前建议

短期验证：

- 继续用 M3 做预标注；
- 但每个候选结果必须人工确认；
- 对 21 秒这类场景，把标签拆成 `two_parcels_visible` 和 `open_no_drop`；
- 不要把 M3 输出直接当训练真值。

中期工程：

- 训练包裹检测模型；
- 训练/规则识别开门状态；
- 用纯视觉状态机判断开门未落。

长期稳定：

- 争取接入 PLC/WCS；
- 没有 PLC 也能做，但报警置信度和可解释性会低一些；
- 有 PLC 后可显著降低误报和漏报。
