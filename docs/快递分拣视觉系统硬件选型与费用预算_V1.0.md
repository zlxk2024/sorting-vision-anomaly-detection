# 快递分拣视觉系统硬件选型与费用预算 V1.0

**版本日期：** 2026-07-26  
**适用范围：** 约100个分拣闸口、一个相机覆盖4个闸口的视觉异常检测项目  
**预算性质：** 项目立项和甲方沟通参考，最终以现场测试、设备型号和厂商正式询价为准

## 1. 建设规模和基本假设

- 闸口数量：约100个；
- 一个相机覆盖4个闸口；
- 相机数量：`100 ÷ 4 = 25台`；
- 相机采集帧率：25～30 FPS；
- 算法推理帧率：最低20 FPS，推荐25 FPS；
- 算法任务：包裹、抽屉、闸口、落袋检测，ByteTrack等目标跟踪，以及不掉件、飘格、一车两件、失速/滞留判断；
- 计算架构：YOLO和异常状态机部署在现场GPU工控机，管理后台部署在服务器；
- PLC、工控机、服务器、相机使用统一时间；
- 每台工控机正常接入5～6路相机，设计上限8路；
- 推荐5台工作工控机，加1台备用工控机。

## 2. 推荐总体配置

```text
100个闸口
    ↓
25台网络摄像机，每台覆盖4个闸口
    ↓
5台工作工控机，每台接入5台相机
    ↓
每台工控机覆盖20个闸口
    ↓
另配1台备用工控机
```

不建议把25台相机全部接入一台服务器。即使单台服务器算力足够，一旦发生硬件、驱动或网络故障，可能导致100个闸口同时失去检测能力。分区部署有利于控制故障影响范围。

## 3. 相机选型

### 3.1 相机类型

本项目可以优先采用海康威视、大华等品牌的普通网络监控摄像机，不一定使用机器视觉工业相机。

推荐基础规格：

```text
分辨率：400万像素
主码流：2688×1520 @ 25 FPS
供电：PoE
协议：RTSP、ONVIF
编码：H.264/H.265
镜头：4mm或6mm定焦，最终根据安装距离测试
功能：宽动态、手动曝光、手动快门、ROI
```

相机内部不需要部署异常检测算法。相机的主要职责是稳定、清晰地采集视频，并把视频流传输给工控机。

### 3.2 价格档次

| 相机档次 | 参考单价 | 25台合计 | 适用性 |
|---|---:|---:|---|
| 经济型4MP网络相机 | 500～800元 | 1.25～2万元 | 可用于验证，拖影风险较高 |
| 推荐型4MP星光级相机 | 800～1,500元 | 2～3.75万元 | 推荐生产测试 |
| 大靶面/电动变焦型 | 1,500～3,000元 | 3.75～7.5万元 | 复杂机位、光照条件较差 |

项目预算建议按每台1,200元计算：

```text
25台 × 1,200元 = 30,000元
```

加上支架、接线盒等附件后，相机部分约3.2万～3.5万元。

### 3.3 选型关键因素

不能只看“400万像素”，还要检查：

1. 主码流是否真正支持400万像素、25 FPS，而不是15 FPS；
2. 是否支持稳定RTSP连续取流；
3. 是否支持PoE，便于集中供电和布线；
4. 是否可以关闭智能编码、强降噪等可能损伤运动细节的功能；
5. 是否支持手动设置曝光时间；
6. 是否支持H.264，便于GPU硬件解码和排查兼容问题；
7. 是否支持宽动态，避免现场灯光和金属反光造成过曝；
8. 固定码率、关键帧间隔和时间戳能否按项目要求配置；
9. SDK、ONVIF或厂商接口是否开放；
10. 长时间运行时是否存在断流、花屏和自动降帧。

### 3.4 快门与照明

普通网络相机用于高速包裹时，最大风险是运动拖影。建议现场验证：

```text
曝光时间：1/500秒～1/1000秒
采集帧率：25～30 FPS
```

快门速度提高后，画面亮度会下降，因此应配置稳定的LED照明。建议照明预算：

```text
每个相机点位：300～800元
25个点位：0.75万～2万元
```

不能依靠增加图像增益弥补亮度，否则会增加噪点并降低包裹和门板识别稳定性。

## 4. 工控机和GPU配置

### 4.1 推荐配置

每台工控机处理5～6路1080P/4MP视频，建议：

| 部件 | 推荐配置 |
|---|---|
| GPU | NVIDIA RTX 2000 Ada 16GB |
| CPU | 12核以上，推荐16核 |
| 内存 | 最低32GB，推荐64GB |
| 系统盘 | 1TB NVMe SSD |
| 视频缓存盘 | 2TB以上NVMe或企业级SSD |
| 网卡 | 双千兆最低，推荐双2.5GbE |
| 电源 | 工业级500W以上，按整机功耗核算 |
| 系统 | Linux + Docker，或甲方指定Windows |
| 时间同步 | 与PLC、服务器使用同一NTP服务器 |

双网口建议：

```text
网口1：相机专用网络
网口2：PLC、服务器和管理网络
```

避免视频流量干扰PLC通信和业务接口。

### 4.2 GPU与相机路数

以下为YOLO11n/YOLO11s、TensorRT FP16、640输入尺寸的工程估算，必须通过真实视频压力测试确认：

| GPU显存 | 建议相机数 | 最大设计相机数 | 说明 |
|---:|---:|---:|---|
| 8GB | 2～4路 | 4路 | PoC使用，不建议大规模生产 |
| 12GB | 4～6路 | 6路 | 小规模试点 |
| 16GB | 5～8路 | 8路 | 推荐生产配置 |
| 20～24GB | 8～12路 | 12路 | 高配置工控机或边缘服务器 |

显存不是唯一决定因素。实际路数还受以下因素影响：

- 视频分辨率和帧率；
- GPU硬件解码能力；
- YOLO模型大小；
- 是否使用分割、关键点或二次分类模型；
- ByteTrack等跟踪计算；
- 视频缓冲和录像转码；
- CPU、内存和PCIe带宽；
- 端到端告警延迟要求。

### 4.3 GPU型号建议

#### RTX 2000 Ada 16GB

- 推荐每台处理5～6路相机；
- 适合YOLO11n/YOLO11s和目标跟踪；
- 公开市场显卡参考价约4,900～5,600元；
- 适合紧凑型工控机和低功耗部署。

#### RTX 4000 SFF Ada 20GB

- 推荐每台处理6～8路，工程上限可测试到10路；
- 适合更大YOLO模型、分割模型和后续算法升级；
- 公开市场显卡参考价约10,499元；
- 20GB ECC显存、低功耗、适合专业工作站或工控机。

#### NVIDIA L4 24GB

- 适合机架式边缘服务器和8～12路以上视频；
- 具有较强视频解码和AI推理能力；
- 被动散热，必须使用具备专用风道的服务器；
- 不建议直接安装到没有合适风道的普通工控机。

## 5. 多路视频软件部署方式

不建议为每个相机单独启动一份完整YOLO模型。推荐所有相机共享一个推理服务：

```text
多路RTSP视频
    ↓
GPU硬件解码
    ↓
每路独立帧缓冲
    ↓
Batch 4/8批量推理
    ↓
一份TensorRT YOLO模型
    ↓
每路独立目标跟踪器
    ↓
每路独立异常状态机
    ↓
PLC订单和抽屉事件关联
    ↓
本地告警与服务器上报
```

软件必须始终优先处理最新帧。当系统负载过高时，应按策略丢弃已经过期的帧，不能让视频帧无限排队，否则报警延迟会持续增加。

## 6. 帧率和算力估算

正常落件最快约0.12秒：

| 推理帧率 | 0.12秒内约有多少帧 | 评价 |
|---:|---:|---|
| 10 FPS | 1.2帧 | 容易漏掉快速动作 |
| 15 FPS | 1.8帧 | 勉强，不够稳定 |
| 20 FPS | 2.4帧 | 第一版可用 |
| 25 FPS | 3帧 | 推荐 |
| 30 FPS | 3.6帧 | 更细致，算力增加 |

建议：

```text
相机采集：25～30 FPS
算法推理：最低20 FPS，推荐25 FPS
原始录像：保持相机原始帧率
```

若一台工控机接入6路相机，每路25 FPS：

```text
6 × 25 = 150帧/秒
```

预留30%算力余量：

```text
150 × 1.3 ≈ 195帧/秒
```

因此整机完整链路应具有约195 FPS的持续处理能力。不能只引用YOLO对单张图片的峰值速度。

## 7. 压力测试和验收

正式定型前必须使用最终相机、最终模型和真实RTSP视频进行至少72小时压力测试。

建议验收条件：

- GPU长期利用率不超过70%～80%；
- 显存长期占用不超过75%～80%；
- CPU平均利用率不超过70%；
- 视频处理队列不持续增长；
- 无明显丢帧或轨迹频繁中断；
- P95视觉处理延迟小于300～500ms；
- 端到端告警延迟满足项目验收要求；
- RTSP断流后能够自动恢复；
- 工控机重启后服务和模型自动启动；
- GPU温度、频率和功耗长期稳定；
- PLC、工控机和服务器时间同步误差不超过500ms，建议控制在100ms以内。

### 9.1 告警灯、音响和IO

| 项目 | 数量 | 参考单价 | 小计 |

| **合计** |  |  | **6.75～18.5万元** |

如果每4个闸口共用一个声光报警器，费用可以降低，但系统必须通过语音、屏幕或不同灯位明确指出具体闸口。

### 9.2 视频存储

如果只保存异常事件前后各15秒，工控机本地2TB缓存盘通常可以满足试点需求。

如果要求25路视频连续保存30天，按每路4Mbps估算：

```text
25路 × 4Mbps × 30天 ≈ 32.4TB原始数据
```

考虑RAID和容量余量，建议配置48～64TB可用存储，预算约5万～10万元。

## 11. 费用边界

本文费用只包含硬件预算，不包含：

- 现场视频数据采集；
- 人工标注；
- YOLO模型训练和优化；
- 多目标跟踪算法；
- 四类异常状态机开发；
- PLC/WCS协议接入；
- 订单、抽屉和视觉轨迹关联；
- 管理后台、APP和大屏；
- 现场安装、布线施工、调试和验收；
- 长期算法运维和重新训练。

上述软件、算法、实施和运维费用应单独报价。
