# 快递分拣视觉 YOLO_V2 模型训练与评估报告

**报告日期：** 2026-07-29
**模型版本：** `sorting_yolo11n_v2_mixed`
**任务类型：** 目标检测（包裹、抽屉打开、抽屉关闭、闸口、落袋）

## 1. 结论摘要

本轮已经完成新场景图片标注、旧/新场景数据合并、YOLO_V2 微调训练和独立测试。

YOLO_V2 在全部独立测试集上的 `mAP@0.5` 为 **0.894**，相比 YOLO_V1 的 **0.732** 提升 **0.162**；在新拍摄场景上的 `mAP@0.5` 从 **0.467** 提升到 **0.829**，提升 **0.361**。说明补充新角度数据并使用旧、新场景联合训练是有效的，模型已经具备作为第二版实体检测模型继续开展时序异常识别验证的条件。

但本轮指标只证明模型能够检测五类视觉实体，不等于已经可靠识别“不掉件、飘格、一车两件、失速/滞留”四类异常。四类异常还需要在 YOLO 检测结果之上增加包裹跟踪、抽屉与闸口空间映射、持续时间判断、PLC 事件关联，并使用独立的事件级标注视频进行评估。

当前不建议直接按生产验收标准上线自动报警，主要风险是：

- 新场景 `drawer_closed` 召回率只有 **0.480**，存在较明显漏检。
- 新场景 `parcel` 精确率为 **0.574**，仍可能把设备结构或运动模糊误识别为包裹。
- 新场景测试集中 `drawer_closed` 只有 14 个实例，统计置信度不足。
- 旧场景 `mAP@0.5:0.95` 比 V1 下降 0.017，说明严格框定位存在轻微回退。

综合判断：**YOLO_V2 达到 PoC/现场试运行阶段的实体识别要求，但尚未达到四类异常无人值守报警的最终验收条件。**

为降低模型只适应某一个拍摄角度的风险，本轮没有仅用新增 100 张图片在 YOLO_V1 上连续训练，而是从 YOLO_V1 权重出发，使用旧场景和新场景混合数据重新微调。

| 数据来源 | 图片数 |
|---|---:|
| 旧场景压缩抽样数据 | 481 |
| 新场景复核数据 | 600 |
| 合计 | **1,081** |

数据划分如下：

| 子集 | 图片数 | 占比 |
|---|---:|---:|
| 训练集 | 754 | 69.8% |
| 验证集 | 162 | 15.0% |

新视频没有随机逐帧拆分，而是按互不重叠的 10 秒时间块划分训练、验证和测试数据，避免相邻帧或近重复画面同时出现在不同集合中，降低指标虚高风险。

## 6. 错误分析

当前主要错误集中在以下方面：

1. **新角度下抽屉开关状态易混淆。**
   同一块门板在不同位置、运动阶段和透视角度下外观变化明显；关闭门板的下沿容易被设备横梁遮挡，模型也可能把平放门板、背景金属板和抽屉结构混淆。

2. **包裹存在误检。**
   白色金属结构、黄色/蓝色机械部件、门板反光以及运动模糊可能被识别为包裹。新场景包裹 Precision 只有 0.574，说明后续异常逻辑若直接使用所有检测框，容易产生假轨迹和误报警。

3. **连续视频帧高度相似。**
   图片数量多不等于有效视觉变化多。连续相邻帧可能只是同一个包裹和同一状态的重复画面，因此训练数据应按事件和状态变化覆盖度衡量，而不能只按图片总数衡量。

4. **标签并非完全独立双人盲审。**
   本轮测试标签来自统一规则下的人工反馈与视觉复核，但还没有完成双人独立标注及冲突仲裁。因此指标适合研发决策，不应直接作为甲方最终验收数据。

5. **单帧检测不能确认动态异常。**
   某一帧看到“门开且包裹仍在抽屉”可能只是正常下落过程。必须结合开门后持续时间、包裹速度和后续帧才能判断不掉件或滞留。

## 7. 对四类异常识别的支持程度

| 异常类型 | YOLO 提供的基础信息 | 仍需增加的逻辑 | 当前状态 |
|---|---|---|---|
| 不掉件 | `parcel`、`drawer_open` | 同一抽屉关联；开门后包裹持续停留超过阈值；排除正常下落过程 | 可开发，尚未事件级验收 |
| 飘格 | `parcel`、`chute`、`bag` | 包裹轨迹；实际落格识别；与 PLC 目标闸口对比 | 缺 PLC/目标格口时只能发现轨迹异常，不能证明错格 |
| 一车两件 | 同一抽屉内多个 `parcel` | 抽屉区域归属；多目标跟踪；去除同一包裹重复框 | 可开发，需要专门双件事件样本 |
| 失速/滞留 | `parcel`、`chute` | 速度估计；闸口区域持续停留时间；运动方向 | 可开发，必须进行连续视频判断 |

建议异常逻辑使用完整视频帧率进行追踪，模型可以每 2～3 帧推理一次，但跟踪与状态机应保留真实时间戳。正常开门到离开抽屉的最慢参考值为 0.65 秒时，初始报警阈值可从约 0.9～1.2 秒验证，最终阈值必须通过现场正常事件分布确定，而不是仅凭单帧设定。

## 8. 推理性能说明

当前在本机 CPU、`320 × 320` 输入条件下，新场景测试的模型纯推理时间约为 **48.7 ms/帧**，理论上约 20.5 FPS。该数字不包含 RTSP 解码、多路调度、跟踪、规则判断、视频存储和告警通信开销，不能直接推算 RTX 3060 能支持的实际摄像头数量。

现场部署前应在目标工控机上用真实 RTSP 码流开展 8、12、16 路阶梯压测，记录：

- 每路实际分析 FPS；
- 端到端告警延迟 P50/P95/P99；
- GPU 显存、GPU 利用率和解码器占用；
- CPU、内存、网络带宽；
- 持续 24～72 小时运行的掉流和积压情况。

## 9. 下一阶段建议和验收门槛

### 9.1 数据补充

- 增加新角度 `drawer_closed` 有效实例至少 **150～250 个**，覆盖清晰、模糊、遮挡、画面边缘和运动状态。
- 增加新场景包裹困难正样本与容易误检的负样本 **200～300 张**。
- 保留旧场景困难样本进行回放训练，重点修复旧场景 `drawer_open` 定位回退。
- 建立独立、不参与训练的测试视频，并由两名标注人员复核四类异常的开始时间、结束时间、目标抽屉和目标闸口。

### 9.2 建议检测模型阶段门槛

| 指标 | 建议进入现场异常联调的最低值 |
|---|---:|
| 新场景 `parcel` Recall | ≥ 0.90 |
| 新场景 `parcel` Precision | ≥ 0.85 |
| `drawer_open` Recall | ≥ 0.95 |
| 新场景 `drawer_closed` Recall | ≥ 0.85 |
| `chute` / `bag` mAP@0.5 | ≥ 0.95 |

YOLO_V2 已达到 `drawer_open`、`chute` 和 `bag` 的建议值，但 `parcel` 与新场景 `drawer_closed` 尚未达到。

### 9.3 异常系统阶段必须单独评估

完成跟踪、PLC 关联和时序状态机后，应按“事件”而不是按“图片”评估：

- 每类异常事件 Precision、Recall、F1；
- 每小时误报警次数；
- 每千件漏报警数；
- 告警延迟 P50/P95/P99；
- 订单号、抽屉号、目标闸口和实际闸口关联正确率；
- 连续运行稳定性和视频断流恢复能力。

建议 PoC 初期先以异常召回率为主，同时把误报警控制在人工可复核范围内；生产验收阈值应在真实异常数量足够后由甲乙双方共同确认。

## 11. 最终判断

本轮联合训练路线正确，新场景适应能力获得显著提升，同时基本保留了旧场景能力。YOLO_V2 可以作为下一阶段“检测 + 跟踪 + PLC 关联 + 时序规则”异常识别系统的基础模型。

当前交付应定义为：

> 五类实体检测 YOLO_V2 研发版已完成并通过混合场景独立测试；四类异常检测尚处于系统联调与事件级验证阶段，不应把目标检测 mAP 直接等同于异常报警准确率。
