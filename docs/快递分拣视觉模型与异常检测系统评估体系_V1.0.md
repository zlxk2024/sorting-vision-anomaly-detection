# 快递分拣视觉模型与异常检测系统评估体系 V1.0

**适用范围：** 包裹、抽屉开/关、闸口、落袋识别，以及不掉件、飘格、一车两件、失速/滞留四类异常检测
**用途：** 算法迭代、PoC 验证、试点测试、项目验收、上线监控
**版本日期：** 2026-07-26

## 1. 评估结论先行

本项目不能只用 YOLO 的 mAP 判断是否可交付。应建立“双层评估 + 生产保障”体系：

1. **模型组件层**：评估目标检测、门状态识别、目标跟踪、空间归属和计时是否准确。
2. **异常事件层**：以完整事件为单位，评估四类异常是否漏报、误报、重复报警以及报警是否及时。
3. **生产系统层**：评估实时性、稳定性、断流恢复、时钟同步、告警灯执行、证据留存和接口可靠性。

正式验收以“事件召回率、每小时误报数、P95 告警延迟、系统可用性”为核心；mAP 只作为诊断指标，不能单独作为验收结论。

## 2. 评估对象和边界

### 2.1 模型输入与输出

- 输入：相机视频流；生产环境建议同时接入 PLC/WCS 的抽屉、目标格口和设备时间数据。
- 感知输出：`parcel`、`drawer_open`、`drawer_closed`、`chute`、`bag` 的框、类别、置信度。
- 跟踪输出：包裹轨迹 ID、抽屉 ID、闸口 ID、落袋 ID，以及实体间归属关系。
- 事件输出：异常类型、开始/结束时间、涉及实体、实际格口、目标格口、置信度、证据图片/视频。
- 告警输出：灯光/音响触发、格口位置、告警时间、确认和处置状态。

### 2.2 四类异常的统一定义

| 异常类型 | 业务定义 | 必要判据 | 不应触发的情况 |
|---|---|---|---|
| 不掉件 | 抽屉已经打开，包裹超过允许时间仍留在抽屉内 | 同一抽屉从关闭转为打开；同一包裹仍属于该抽屉；超过宽限时间仍无正常向下位移 | 正常开门后 0.65 秒内完成离开；检测偶发漏框 |
| 飘格 | 应落入 A 闸口的包裹实际进入 B 闸口 | 明确目标闸口 A；轨迹进入实际闸口 B；A≠B | 仅看到横向运动但无法确定目标闸口 |
| 一车两件 | 同一个抽屉同时承载两个及以上独立包裹 | 同一抽屉 ID 关联至少两个独立包裹轨迹，并持续达到确认时间 | 画面同框两个包裹，但分别属于不同抽屉 |
| 失速/滞留 | 包裹停留在闸口或滑道上方，未在正常时间内继续下落 | 包裹进入滞留区域；速度/位移低于阈值；停留时间超过阈值 | 正常短暂停顿、遮挡导致的假静止 |

**关键边界：** 没有 PLC/WCS 时，视觉可以判断“实际落入哪里”，但不一定知道业务上“应该落入哪里”。因此，飘格正式验收应优先使用 WCS/PLC 提供的目标格口作为真值；纯视觉推断只能作为较低置信度候选。

## 3. 总体评估架构

| 层级 | 评估内容 | 主要指标 | 是否可单独决定验收 |
|---|---|---|---|
| 数据层 | 数据覆盖、标注质量、数据泄漏 | 标注准确率、一致性、覆盖矩阵、泄漏检查 | 否，但不合格时禁止继续 |
| 检测层 | 五类目标识别 | Precision、Recall、F1、AP50、AP50-95、IoU | 否 |
| 跟踪与关系层 | ID 连续性、包裹与抽屉/闸口归属 | IDF1、HOTA、ID Switch、归属准确率 | 否 |
| 事件层 | 四类异常识别 | 事件 Precision/Recall/F1、误报/小时、漏报率、重复率、延迟 | 是，核心验收层 |
| 系统层 | 实时、稳定、告警执行、证据链 | FPS、P95 延迟、可用性、断流恢复、告警成功率 | 是，核心验收层 |
| 运营层 | 现场使用效果 | 有效告警率、处置时长、人工负担、问题闭环率 | 上线持续评估 |

## 4. 数据集和真值体系

### 4.1 数据划分规则

- 禁止把同一事件的相邻帧随机拆到训练集和测试集。
- 按“站点—日期—相机—连续视频段”分组划分；测试集必须包含训练时未见的日期和连续视频段。
- 生产泛化验收建议至少包含不同光照、班次、包裹材质、尺寸、速度、遮挡、机位抖动和网络状态。
- 测试集冻结后，任何参数调优都不得使用测试集；调优只能使用训练集和验证集。
- 正常视频必须占足够比例，否则无法可靠计算每小时误报数。

### 4.2 事件真值记录

每个真值事件至少包含：

`event_id、site_id、camera_id、video_id、event_type、start_time、end_time、parcel_track_ids、drawer_id、expected_chute_id、actual_chute_id、bag_id、severity、annotator_1、annotator_2、review_status、evidence_path、notes`

### 4.3 标注质量门槛

| 项目 | 建议门槛 |
|---|---:|
| 五类目标框抽检准确率 | ≥ 98% |
| 事件类型、起止时间、实体归属准确率 | ≥ 98% |
| 两名标注员事件类型一致率 | ≥ 95% |
| 争议样本专家复核率 | 100% |
| 测试集重复帧/同事件泄漏 | 0 |

### 4.4 推荐测试规模

| 阶段 | 每类真实异常事件 | 正常视频 | 场景范围 | 用途 |
|---|---:|---:|---|---|
| PoC | ≥ 50 | ≥ 4 小时 | 单站点、单机位 | 判断技术路线是否可行 |
| 试点 | ≥ 200 | ≥ 24 小时 | 多日期、多班次 | 调整阈值、验证现场稳定性 |
| 正式验收 | ≥ 300 | ≥ 72 小时 | 至少 3 天，建议跨机位/站点 | 形成可审计验收结论 |

若某类事件在 300 个独立样本中 0 漏报，按“3/n”经验上界，其 95% 置信水平下的漏报率上界约为 1%。稀有事件可采用“真实事件 + 可控复现”，但必须分别报告，不得混成一个数字。

## 5. 模型组件评估

### 5.1 目标检测

逐类报告 Precision、Recall、F1、AP50、AP50-95 和定位 IoU，并单独建立以下困难子集：

- 快速运动/拖影；
- 黑袋、白袋、纸箱、小件和异形件；
- 包裹被立柱或机构遮挡；
- 抽屉位于画面边缘或不完整；
- 强反光、暗光、相机抖动；
- 多包裹相邻或重叠。

对 `parcel` 和 `drawer_open` 优先保障 Recall。阈值不能仅选择总体 F1 最高点，应结合漏报成本和误报成本确定。

### 5.2 门状态与空间关系

必须独立报告：

- 抽屉打开/关闭状态准确率和混淆矩阵；
- 抽屉 ID 定位准确率；
- 包裹—抽屉归属准确率；
- 包裹—实际闸口归属准确率；
- 目标闸口—实际闸口比对准确率；
- 开门时刻、离开抽屉时刻的时间误差 MAE/P95。

统一视觉定义：**打开门板近似水平；关闭门板近似竖直；机械背板、底座、滑道不得标为抽屉。画面边缘不完整抽屉不标。**

### 5.3 跟踪

| 指标 | 含义 | 重点风险 |
|---|---|---|
| IDF1 / HOTA | 轨迹识别和关联综合质量 | 快速包裹 ID 丢失或换 ID |
| ID Switch / 100 条轨迹 | 每 100 条轨迹发生的换 ID 次数 | 一件被误认为两件 |
| Fragmentation | 同一实体轨迹被切碎次数 | 不掉件计时被重置 |
| 轨迹完整率 | 从抽屉到闸口/落袋可连续追踪的比例 | 飘格无法闭环 |
| 归属准确率 | 轨迹与抽屉、闸口、落袋关系正确率 | 一车两件和掉错格判断错误 |

## 6. 异常事件评估

### 6.1 事件匹配规则

预测事件与真值事件同时满足以下条件才计为 TP：

1. 异常类型相同；
2. 涉及的关键实体一致（同一抽屉/闸口，或同一包裹轨迹）；
3. 预测报警时间落在允许窗口内，或预测/真值时间段达到约定重叠；
4. 同一真值事件的多次报警只计 1 个 TP，其余计为重复报警。

未匹配预测为 FP，未匹配真值为 FN。必须按事件统计，不能把一段异常里的几十帧当作几十个正确样本。

### 6.2 核心公式

- 事件精确率 `Precision = TP / (TP + FP)`
- 事件召回率 `Recall = TP / (TP + FN)`
- `F1 = 2 × Precision × Recall / (Precision + Recall)`
- 每小时误报数 `FAR/h = FP / 正常视频小时数`
- 每百事件漏报数 `FN100 = 100 × FN / 真值事件数`
- 重复报警率 `重复报警数 / 所有预测报警数`
- 告警延迟 `报警时刻 - 可判定异常时刻`，报告 P50、P95、P99

### 6.3 各事件的可判定时刻

| 事件 | 可判定异常时刻 |
|---|---|
| 不掉件 | 抽屉打开后超过宽限时间，包裹仍留在同一抽屉 |
| 飘格 | 轨迹进入非目标闸口并达到确认线/确认区域 |
| 一车两件 | 同一抽屉稳定关联第二个独立包裹并达到确认时间 |
| 失速/滞留 | 包裹在滞留区域的低速停留超过阈值 |

当前已知正常“开门至包裹离开抽屉”最慢约 0.65 秒。PoC 可将不掉件告警宽限设为 0.8 秒，并通过验证集寻找兼顾漏报与误报的阈值；正式阈值应按设备速度和包裹类型分层标定。

## 7. 建议验收门槛

下表是建议起点，最终数值应由甲乙双方根据异常损失、现场频率和硬件条件写入验收条款。

| 指标 | PoC | 试点 | 正式验收建议 |
|---|---:|---:|---:|
| 不掉件事件召回率 | ≥ 85% | ≥ 95% | ≥ 98% |
| 飘格事件召回率 | ≥ 80% | ≥ 90% | ≥ 95% |
| 一车两件事件召回率 | ≥ 85% | ≥ 95% | ≥ 98% |
| 失速/滞留事件召回率 | ≥ 85% | ≥ 95% | ≥ 98% |
| 四类事件总体精确率 | ≥ 80% | ≥ 90% | ≥ 95% |
| 每相机每小时误报数 | ≤ 3.0 | ≤ 1.0 | ≤ 0.2 |
| 重复报警率 | ≤ 10% | ≤ 5% | ≤ 2% |
| P95 端到端告警延迟 | ≤ 2.0 秒 | ≤ 1.5 秒 | ≤ 1.0 秒 |
| 关键实体归属准确率 | ≥ 90% | ≥ 95% | ≥ 98% |
| 系统可用性 | — | ≥ 99.0% | ≥ 99.5% |
| 告警灯/音响触发成功率 | — | ≥ 99.0% | ≥ 99.9% |
| 系统与上游时间同步误差 | ≤ 500 ms | ≤ 500 ms | ≤ 500 ms |

**硬性否决项：** 任一关键异常召回率低于门槛、误报率超标、P95 延迟超标、告警输出失败率超标，均不得用其他高分抵消。

## 8. 生产系统评估

### 8.1 性能与实时性

- 按真实相机分辨率、帧率和并发路数测试；
- 报告采集、解码、推理、跟踪、规则、告警输出各阶段 P50/P95/P99 延迟；
- 连续满载 24/72 小时压力测试，记录 FPS、CPU/GPU、内存、温度和降频；
- 任何队列积压必须受控，禁止延迟不断累积。

### 8.2 稳定性与故障恢复

- RTSP 断流、丢包、花屏、相机重启后的自动恢复时间；
- 工控机重启后的服务自启动和模型加载时间；
- 网络中断时本地继续检测、缓存和告警的能力；
- 服务器恢复后的数据补传、幂等和去重；
- 磁盘满、日志膨胀、时间漂移和配置损坏保护。

### 8.3 告警和证据链

- 告警灯/音响实际触发成功率；
- 告警包含正确格口、异常类型和时间；
- 每个事件保存关联运单图片和前后各 15 秒视频；
- 证据文件、事件记录、模型版本、规则版本和时间戳可互相追溯；
- 告警确认、关闭、误报标记和处置结果可审计。

## 9. 鲁棒性切片

总指标合格不代表所有场景合格。以下切片均需单独报告事件召回率和误报率：

| 维度 | 典型切片 |
|---|---|
| 时间/光照 | 白天、夜间、强反光、局部阴影 |
| 包裹 | 黑袋、白袋、纸箱、小件、大件、异形件、反光件 |
| 运动 | 正常速度、高速、拖影、震动、风吹 |
| 遮挡 | 立柱遮挡、机构遮挡、包裹相互遮挡 |
| 机位 | 中央、边缘、轻微偏移、抖动 |
| 负载 | 单件、连续密集、同框多件 |
| 网络 | 正常、抖动、丢包、断流恢复 |

某一高风险切片样本不足时，报告必须标为“证据不足”，不能并入总体平均后宣称通过。

## 10. 评估流程与发布门禁

1. **冻结版本**：记录模型文件 SHA256、代码提交、规则配置、相机参数、运行环境。
2. **冻结盲测集**：测试集由独立人员保管，算法人员不可看答案调参。
3. **离线回放**：按原始时间速度回放，生成逐帧检测、轨迹和事件记录。
4. **自动计分 + 人工复核**：自动匹配 TP/FP/FN，争议事件由两人复核。
5. **影子运行**：现场运行但不触发人员，先评估真实误报和延迟。
6. **小范围试点**：接入告警灯，观察处置效果和干扰程度。
7. **正式验收**：按冻结门槛和样本规模出具报告，甲乙双方签字。
8. **上线监控**：周/月度统计漂移、误报、漏报和设备故障。

每次漏报或误报都应进入“困难样本回归集”。新模型必须同时通过固定测试集和回归集，且不得为了降低误报明显牺牲关键异常召回率。

## 11. 综合评分卡

| 模块 | 权重 | 评分内容 |
|---|---:|---|
| 异常检测效果 | 45% | 四类事件 Recall、Precision、F1 |
| 误报与及时性 | 20% | FAR/h、重复率、P95/P99 延迟 |
| 检测跟踪与关系 | 15% | 五类识别、ID 连续性、实体归属 |
| 鲁棒性 | 10% | 各困难切片最差表现和稳定性 |
| 系统可靠性 | 10% | 可用性、断流恢复、告警执行、证据链 |

总分只用于排序和迭代。硬性门槛失败时，即使加权总分较高，也判定不通过。

## 12. 当前 V1 基线

### 12.1 YOLO 独立测试集结果

当前模型基于同一个约 39 秒手机视频的 1,184 帧训练，按完整秒划分为训练 944 帧、验证 120 帧、测试 120 帧。

| 类别 | Precision | Recall | mAP50 | mAP50-95 |
|---|---:|---:|---:|---:|
| 全部 | 0.892 | 0.838 | 0.883 | 0.599 |
| parcel | 0.770 | 0.759 | 0.843 | 0.384 |
| drawer_open | 0.799 | 0.598 | 0.644 | 0.307 |
| drawer_closed | 0.909 | 0.846 | 0.941 | 0.550 |
| chute | 0.985 | 0.988 | 0.995 | 0.829 |
| bag | 0.995 | 1.000 | 0.995 | 0.927 |

### 12.2 当前判定

- `chute`、`bag`、`drawer_closed` 已表现出较好同场景识别能力；
- `parcel` 在快速运动、拖影情况下仍可能漏检或重复框；
- `drawer_open` 是当前最弱类别，Recall 仅 0.598，直接影响不掉件计时；
- 当前事件算法已能在样例视频中产生不掉件和飘格候选，但只有一个短视频，无法计算有代表性的事件召回率和每小时误报数；
- 一车两件必须基于“同一抽屉关联两个独立包裹轨迹”，不能用“同框两个包裹”替代；
- 当前阶段结论为 **PoC 可行性基线，不具备生产验收资格**。

## 13. 下一轮最小执行计划

1. 建立冻结的事件真值表，先复核当前视频全部事件；
2. 补充 `drawer_open`、快速包裹和遮挡包裹数据；
3. 采集至少 4 小时正常视频，用于计算真实误报率；
4. 每类收集至少 50 个独立异常事件，完成 PoC 事件级评估；
5. 使用本体系模板生成首版评分卡，确定试点阈值；
6. 接入 PLC/WCS 后重新验证飘格的目标格口比对；
7. 试点阶段扩展到多日期、多班次和至少 24 小时正常视频。
