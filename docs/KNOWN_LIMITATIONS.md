# 已知限制

保留原离线分析入口；新增实时采集、增量异常规则和 SQL 入库服务。模型训练权重未变更。

- 新场景包裹误检、关闭抽屉漏检仍是现有模型短板。
- 新场景按十秒块隔离，但旧场景按秒划分仍有近邻视频帧相关性；未完成独立机位/日期泛化验收。
- 原离线 Python 异常判据含固定像素和帧数阈值；实时入口改用归一化 ROI 和实际秒数。两者改变机位、业务速度或可见范围后均需重新标定，不能直接比较两种规则的事件数。
- 原视频脚本积累整段结果后分析；实时入口使用最新帧缓冲与持久化队列，已验证一路 RTSP。多路吞吐、真实相机、目标工控机及长时间稳定性仍需现场验收。
- 实时入库已验证 PostgreSQL/SQLite；MySQL 驱动已实现，真实实例验证因官方镜像下载 TLS 错误未完成。证据/队列保留容量与归档需运维规划，磁盘满无法保证持久化。
- 没有 PLC/WCS 目标格口时，飘格仅是视觉轨迹候选，不能认定订单错分。
- Horus 状态机没有轨迹 ID，按区域排序关联；滞留只判断持续占用，移动包裹也可能报警。C++ 仅实现三类候选，没有实现飘格；置信度为固定值。
- `.rknn`、交叉编译后的相机应用及厂商 SDK/运行库尚未包含；目录内 `.onnx` 不等于已完成板端部署。
- 原始硬件预算和报价文件为历史方案，未重新询价。
- 某些历史可视化脚本优先使用 macOS 字体；Linux 下需配置可用字体。主推理流程不依赖这些字体脚本。
- 模型辅助预标注使用外部服务，需自行配置环境变量并确认现场数据使用范围；默认识别和验证流程不调用这些脚本。
